# noxeval 0.5: ungrounded details, a deterministic check for RAG answers

Status: approved by Marcus (2026-10-06), implemented the same day. Additive: without `grounding` in the config, a run behaves exactly like 0.4.

## Why

The judge can say an answer "looks supported", but it is a model grading a model. Nox found a cheaper, explainable first layer: every **checkable detail** of the answer (a number, an acronym, a proper name) has to appear in the context the model received. A detail in no passage was invented, or copied from the question.

In Nox this check ran for two weeks before anything else. Its findings, which shape the rules below:

- **Baseline:** 1 of 37 answers flagged, and it was the extractor's fault ("Python Marcus" glued into one name). No invented detail. The rule needs a short allow list (the app's own names) and must split names at those.
- **Numbers come in many spellings:** "10 mil", "10.000", "10,000" and "dez mil" are the same number. Without that, half the flags are false.
- **The question is bait:** "Did he win a prize in 2024?" puts 2024 in the answer even when the model is correcting it. A detail from the question passes only in a sentence that negates it ("I didn't find a prize in 2024").
- **Arithmetic is not invention** (found in Nox in October 2026): "joined in 2023, left for Vibetex 3 years later, in 2026". The 3 is in no passage, but it is the difference between two years that are. A number of years passes when it equals the difference between two grounded years in the same answer and is written as years ("3 anos", "3 years"); "3 projects" does not.

## The check

- Config `grounding?: "off" | "report" | "check"` (default `"off"`), CLI `--grounding report|check`.
  - `report`: measure only. The report lists the answers with ungrounded details; no case fails. This is how Nox started, and how a team should start.
  - `check`: an ungrounded detail fails the case with the code `ungrounded`, a **usefulness** failure (with `repeat`, it is weighed against `minPassRate` like the other quality failures).
- Needs `TargetResponse.context` (RAG passages and tool results). A case whose target returns no context is reported as "not checked", never as grounded.
- Config `groundingAllow?: string[]`: names the answer may always say (the assistant's name, the person or company the app is about, its own channels).
- Case field `grounding?: false` to skip a case (a refusal case, for example, has nothing to ground).
- What is extracted, per sentence: numbers with their multiplier words (pt and en: "mil", "thousand", "milhões", "million", "k"), acronyms (two or more capitals, a capital with a digit, or a leading dot as in ".NET") and capitalized names outside the start of a sentence, joined by connectors ("Rio de Janeiro"). Identifiers glued to letters ("BM25", "v1.2", "gpt-4o") are not numbers.
- Comparison ignores accents and case; names match as whole words, with a plural "s" allowed; a composed name passes when each meaningful word is in the context.

## Report

- `grounding: { mode, answers, checked, withUngrounded, cases: [{ id, details: string[] }] }` in the report; a "Ungrounded details" table in the Markdown summary; the terminal prints the count and the first details.
- With `repeat > 1`, the first attempt is checked (as with the judge). Checking every attempt is cheap here (no model call), but reporting it per attempt is noise; `check` mode does check every attempt, since it can fail the case.

## Programmatic API

Exported, pure: `extractDetails(text, { allow })`, `ungroundedDetails(answer, context, { question, allow })` and `canonicalNumber(raw)`, plus the helpers they use. (Changed during implementation: no `locale` option. The number words and connectors of pt and en live in one table, so the extractor never needs to know the language.) Nox imports them instead of keeping its own copy (`src/domain/grounding.ts` on the site), so the rules live in one place.

## Out of scope

- Meaning ("worked at" becoming "led"). That is the judge's job; Nox measures it as a separate "support" question and keeps it out of production for cost.
- Per-sentence citation checks (`[n]` pointing to the right passage). They need the app to number its sources; noxguard 0.3 brings that as a runtime guard. noxeval stays black-box.
- Languages beyond pt and en for number words.
